# Wave 0 (M0 Foundation) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up the AvaLab monorepo skeleton so that a real audio file can be uploaded to the API (validated, normalized, stored with TTL, served with Range), a golden-vector pipeline feeds the pure-TS DSP package, the bilingual RTL web shell runs, and the whole stack boots under `docker compose` — all checks green.

**Architecture:** Monorepo with pnpm workspaces (`apps/web`, `packages/dsp`) plus two uv Python projects (`apps/api`, `tools/golden`). Browser-side DSP is pure TypeScript in `packages/dsp`, verified against JSON fixtures generated by NumPy/SciPy. API is FastAPI under `/api/v1`, OpenAPI exports to a generated TypeScript client. Web is React + Vite + Tailwind, i18next with Persian RTL default. Deployment is Docker Compose (static web behind Caddy proxying `/api` to the API container).

**Tech Stack:** TypeScript strict + Vite + React, Biome (lint+format), Vitest, Playwright (chromium), Zustand (later waves), i18next, Tailwind (CSS-first config), pnpm workspaces; Python 3.12 + uv + FastAPI + pydantic-settings + pytest + ruff + mypy; ffmpeg/ffprobe as subprocesses; Docker Compose + Caddy.

**Spec:** `AGENTS.md` (authority) + `docs/DECISIONS.md` (D-001…D-006 rulings).

## Global Constraints (bind every task)

- TypeScript `strict: true`, `noUncheckedIndexedAccess: true`, no `any`, no `@ts-ignore` without a justifying comment.
- No hard-coded user-visible strings — every UI string goes through i18next (`fa` default RTL, `en` LTR). No `left/right/margin-left/padding-right`; logical properties only (`ms-*`, `me-*`, `ps-*`, `pe-*`, `start/end`).
- Quantities carry units in names: `durationSeconds`, `sampleRateHz`, `cutoffHz`, `gainDb`, — never bare `duration`, `rate`.
- Input limits (exact): max duration **300 s**, max upload **100 MB (104857600 bytes)**, max sample rate **96000 Hz** (resample above, tell the user), max channels **2** (downmix above), TTL default **60 min**.
- Uploads are untrusted: validate with ffprobe (never extension/MIME), enforce limits **before** heavy work, ffmpeg/ffprobe always spawned with **argument arrays** (never shell strings), filenames sanitized, storage under server-generated UUIDs only.
- Errors: stable machine-readable codes, English message text; frontend translates by code. Error body shape exactly `{"error": {"code": "<code>", "message": "<text>"}}`.
- No secrets committed; `.env.example` committed, real `.env` ignored. GPL-3.0 project — new dependencies must be GPLv3-compatible (MIT/BSD/Apache fine) and recorded in `docs/THIRD_PARTY.md`.
- Conventional Commits, exact messages given per task. Never commit build output, model weights, or real `.env`.
- Every long command must be actually run in-session before claiming pass. No fabricated results.
- CI provider undecided (no remote yet) — local `pnpm check` + `uv` checks are the gate; do NOT add GitHub Actions files in this wave.

## Review Focus (spec-implied failure modes; each has a pinning test in the owning task)

1. **Limits enforced before heavy work + no leftovers on failure** — oversize/overlong/anonymous streams rejected with the right code, and a failed ingest leaves zero temp files behind (T6, T7).
2. **Range request edges** — `bytes=100-`, `bytes=-100`, `bytes=0-`, out-of-range → 416 with `Content-Range: bytes */<size>` (T8).
3. **i18n checker false-green** — the checker must FAIL on a real missing key / unused key / parity gap via its own fixture tests, and must not false-fail on allowlisted dynamic namespaces (T11).
4. **Backend offline behavior** — web shell renders fully with API unreachable, shows the translated offline state, shows no raw fetch error, no console errors (T10 Playwright with API stopped).
5. **RTL correctness + Latin technical digits** — `dir` switches with language, Persian font renders, layout uses logical properties (no mirrored offsets), technical readouts stay LTR (T10 smoke asserts `dir` and layout direction; later waves extend).
